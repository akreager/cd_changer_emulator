## 1. Purpose and Scope

This document defines the test procedures for reverse engineering the serial communication protocol between a Kenwood KRC-3006 aftermarket car stereo head unit and its companion CD changer, connected via a 13-pin mini-DIN connector. The objective is to fully characterize the protocol—message structure, timing, command set, and handshake behavior—to enable future development of a hardware emulator.

The procedures are structured in sequential test phases, each building on the results of the previous phase. Each phase has defined entry criteria, step-by-step procedures, expected results, and pass/fail criteria. All test results shall be recorded in the companion Test Log workbook (TL-KRC3006-01.fods).

This document covers only protocol capture and analysis. Emulation development and integration testing are covered separately in TP-KRC3006-03.

This document is modeled on the IEEE 829-2008 standard for test documentation, adapted for hardware protocol reverse engineering. It is intended for publication as part of an open-source project and should be treated as a living document updated throughout the project.

## 4. Test Phases

Testing is divided into sequential phases. Each phase has entry criteria that must be satisfied before beginning. Do not skip phases; later phases depend on validated results from earlier ones.

### 4.1 Phase 1: Bench Setup and Static Verification

**Objective:** Establish a powered bench test setup and verify the 13-pin DIN connector pinout against the factory service manual schematic. Confirm power, ground, and signal voltage levels with KDC-C717 connected inline through MOD-03.

**Entry Criteria:** Head unit (KEN-01), bench PSU (PWR-01), staged power adapter (PWR-02), KRC-3006 DC cord (PWR-03), multimeter (DMM-01), 13-pin mini-DIN cable (CBL-01), pass-through breakout (MOD-03 S/N 1), KDC-C717 changer (KEN-02), and service manual available. Phase 1 setup text is aligned with the 2026-04-19 execution under R-1.6; the published record is unchanged.

**Reference:** Record all measurements on Test Log Tab “Phase 1 — Static Verification.”

#### 4.1.1 Power Harness Preparation

1. Identify the head unit power connector using the service manual wiring diagram. Locate the +12 V constant (B+), +12 V accessory/ignition (ACC), ground (GND), and illumination wires.

2. Set the bench PSU to 12.0 V with a current limit of 2.0 A. Do not turn on yet.

3. Connect the bench power supply output to the staged power adapter input. Ensure both toggle switches (constant power and ignition power) are in the OFF position.

4. Connect the staged power adapter output harness to the head unit DC cord.

> **CAUTION:** The KRC-3006 may draw a brief inrush current on power-up. If the PSU trips, increase the current limit to 3 A momentarily, then reduce after startup. Typical running current is 0.5–1.5 A.

#### 4.1.2 Initial Power-Up

1. Turn on the bench PSU.

2. Turn on the constant-power toggle on the staged power adapter. This provides battery-unswitched power (B+) to the head unit for memory retention.

3. Turn on the ignition-power toggle on the staged power adapter. Verify the head unit powers on and displays normally.

4. Record the steady-state current draw on the test log (expected: 0.5–1.5 A at idle with no audio playing).

5. Set the head unit source to CD CHANGER (may require pressing SRC or a dedicated CD-CH button). The expected display is E-01 (no magazine), per R-1.6. Record the exact display text.

#### 4.1.3 13-Pin DIN Static Voltage Measurements

1. With the head unit powered on and set to CD changer source, use the multimeter to measure DC voltage on each of the 13 pins relative to pin 2 (GND). Record every measurement on the test log form.

2. Cross-reference each measured voltage against the expected values in the following pinout table. Flag any discrepancies for investigation.

**13-Pin DIN reference** — factory names from [DN-02 §1](DN-KRC3006-02.md#1-cd-changer-connector-pinout); aliases second. Unresolved behavior is tested in Phases 2A/2C under [R-1](../.agents/rulings/2026-10-16.md). Phase 1 evidence is [TL-01-P1-20260419](records/TL-KRC3006-01-P1-20260419.pdf), voltage and continuity tables.

| Pin | Signal Name | Function | Direction | Notes |
|---|---|---|---|---|
| 1 | /REQ H (CH-REQH) | Request (H→C) | Output | Observe assertion level and transfer order in §4.2.2. |
| 2 | GND | Ground | — | Measurement reference. |
| 3 | B.U. (+12V) | Battery unswitched supply | Output | Verify voltage per step 3. Never connect to the analyzer. |
| 4 | ON (CH-CON) | Changer enable | Output | Polarity open: Phase 1 DMM HIGH with CD-CH selected; CX85 SM active-LOW. |
| 5 | MUTE (CH-MUTE) | Mute request | Input (CX85 analysis) | Polarity open: Phase 1 idle 0 V / enabled 3.5 V; DN-02 §16.4 active-LOW. Resolve by CH7 capture. |
| 6 | D. GND (published alias AGND) | Digital ground | — | Phase 1 records continuity to pin 2; disposition remains under DC-02. |
| 7 | RESET (CH-RST) | Reset | Output | Phase 1 idle 0 V conflicts with Rev B expected HIGH; observe CH6 and power-on pulse. |
| 8 | R ch (R-CH) | Right audio | Input | Analog audio from changer. |
| 9 | /REQ C (CH-REQC) | Request (C→H) | Input | Observe assertion level and transfer order in §4.2.2. |
| 10 | DATA C (CH-DATAC) | Data (C→H) | Input | Phase 1 idle 5.11 V versus predicted LOW; observe CH2. |
| 11 | DATA H (CH-DATAH) | Data (H→C) | Output | Determine decoder sampling edge in §4.2.3. |
| 12 | L ch (L-CH) | Left audio | Input | Analog audio from changer. |
| 13 | /CLK (CLK) | Clock | Open; CX85 SM lists I/O | 125 kHz assumed, unmeasured. Measure in Phase 2A; identify driver in Phase 2C. |

3. Verify pin 3 shows +12 V (±0.5 V). This confirms the head unit supplies power through the changer port.

4. Verify pin 4 (CH-CON) state when CD changer source is selected and when switched to another source (radio, tape). Toggle the source and record both states. Polarity remains open: Phase 1 measured HIGH with CD-CH selected; the CX85 manual describes active-LOW. Apply §4.2.2 to resolve it (R-1.3).

5. Measure pin 13 (CLK). If the head unit is actively polling for a changer, you may see a DC average voltage between 0 and 5 V (the clock is toggling). A true 0 V or 5 V means the clock is static. Record the observed value.

6. Verify pin 6 (D. GND) has continuity to pin 2 (GND) OR is isolated. Record which. Phase 1 recorded continuity; retain any new discrepancy as an incident.

**Pass Criteria:** Pin 2 is ground. Pin 3 reads 11.5–12.5 V. Pin 4 toggles with source selection. All pins measured and recorded. No unexpected short circuits detected.

**Incident Handling:** If pin 3 shows 0 V, check whether the head unit requires ACC/ignition to enable changer power. If any signal pin shows a voltage outside the analyzer’s specified input range (5.25 V maximum for LA-01, R-1.1), STOP and investigate using the service manual schematic before connecting the logic analyzer.

### 4.2 Phase 2A: Idle capture, changer connected, no magazine

**Authority:** [R-1.1–R-1.3 and R-2](../.agents/rulings/2026-10-16.md); DN-02 §8 items 1–3. This replaces the head-unit-only procedure: the owner reports that CD-CH cannot be selected without a changer present (Phase 1 supplement pending under DC-02).

**Objective:** Capture the inline initialization and idle traffic with the C717 magazine removed (E-01), measure timing, and record the unresolved signal behavior.

**Entry criteria:** Phase 1 passed (owner disposition of its incomplete record is required); MOD-03 S/N 1 verified per TP-02; KDC-C717 connected; LA-01 and PulseView available.

**Reference:** TL-01 tab “Phase 2A — Idle Capture”.

#### 4.2.0 Pre-capture checks

1. Remove bench power before changing wiring. With the changer cable unplugged, measure resistance to GND at J3-10 (DIN pin 11, DATA H) and J3-11 (DIN pin 13, /CLK). DN-02 Rev C predicts about 100 kΩ for R145/R146. Record actual values in Ω; this checks the prediction, not a previously measured fact.
2. Assemble the inline chain with power removed: KRC-3006 → 13-pin cable → MOD-03 S/N 1 J1 → J2 → KDC-C717 cable → KDC-C717. Jumper audio J4 ↔ J5 with a 3.5 mm TRS cable. Remove the magazine.
3. Measure B.U. (DIN pin 3) with power on, once on tuner and once on CD-CH; record both voltages. Expect it to stay constant. Measure at the PSU side or DIN connector as specified in R-1.3, never at J3. Return both staged-adapter switches to OFF before connecting probes.

#### 4.2.1 Analyzer setup and capture settings

1. With bench power removed, connect the custom crimped harness to the female J3 socket using this map. Tape over exposed joints on the back. Block J3-3 with a heat-shrink-capped cut-off pin or blank plug; leave harness position 3 empty. Ground only at J3-1 and leave J3-5 empty. No series resistors go in the analyzer leads (owner decision, R-2).

| LA channel | J3 pin | DIN pin | Signal |
|---|---|---|---|
| CH0 | 11 | 13 | /CLK (CLK) |
| CH1 | 10 | 11 | DATA H (CH-DATAH) |
| CH2 | 9 | 10 | DATA C (CH-DATAC) |
| CH3 | 6 | 1 | /REQ H (CH-REQH) |
| CH4 | 7 | 9 | /REQ C (CH-REQC) |
| CH5 | 2 | 4 | ON (CH-CON) |
| CH6 | 4 | 7 | RESET (CH-RST) |
| CH7 | 8 | 5 | MUTE (CH-MUTE) |
| GND | 1 | 2 | GND |

2. Verify the analyzer is recognized in PulseView and record its software version. The SparkFun TOL-18627 limits are 8 channels, 24 MHz maximum, 5.25 V maximum input, >100 kΩ input impedance with 5 pF, HIGH ≥2.0 V and LOW ≤0.8 V (R-1.1; [SparkFun product page, REF-006](https://www.sparkfun.com/usb-logic-analyzer-24mhz-8-channel.html)). Phase 1's highest reading was 5.15 V on CLK, only 0.10 V below the maximum. B.U. must never reach the analyzer. The SparkFun page also warns that the supposed GND adjacent to input 6 is not ground on some units; do not use that pin. Verify the analyzer ground before connection.
3. Run the first capture of each session at 24 MHz to establish bit timing; 125 kHz is only an assumption. Later captures may use at least 16× the measured bit rate. Every capture lasts at least 10 s, long enough to include the action and hold below; start it before the transition.
4. Record file name, sample rate, trigger and configuration letter for every capture. Save each `.sr` with a matching `.png` in the Capture File Log (§6). These settings and the channel map also apply to Phases 2B and 3; Phase 2C changes CH6 and always uses 24 MHz.

#### 4.2.2 Capture sequence and observations

1. Keep the magazine removed (E-01). Run the following sequence. Repeat B three times, returning to tuner before each B capture. All changes to probe wiring require power removed (§7).

| Config | Start state | Action during capture | Files |
|---|---|---|---|
| A | Both staged-adapter switches OFF; capture started | Constant power ON, then ignition ON; leave source on tuner for 10 s. | `P2A_A_001.sr` and matching PNG |
| B | Powered, source on tuner; capture started | Select CD-CH; hold 15 s. | `P2A_B_001.sr` through `P2A_B_003.sr` and PNGs |
| C | Powered, source on CD-CH; capture started | Select tuner; hold 5 s, within a capture lasting at least 10 s. | `P2A_C_001.sr` and matching PNG |

2. Record every observation below in TL-01, including capture references, configuration, observed value, resolution, P/F and notes. These are R-1.3's rules; do not infer polarity from a name or overbar.

| Question | Observation | Resolution rule |
|---|---|---|
| ON polarity | CH5 in A/B/C and DMM voltage on DIN pin 4 on tuner and CD-CH | Active-HIGH **at the connector** only if CH5 is HIGH only while CD-CH is selected and traffic starts only after it rises in every capture. Any other pattern is an incident. The CX85 manual's active-LOW may refer to an inverted internal input (DN-02 §16.1); retain this as a note. |
| CLK idle level | CH0 between bursts in B | Record HIGH or LOW; Phase 1's 5.15 V DC predicts HIGH. |
| Bit clock rate | CH0 period within each of 10 bursts | Record mean and range of period and corresponding bit rate. |
| Frame structure | CH0 edges per burst; /REQ H and /REQ C order and polarity | Record which REQ asserts first, its active level and bits per burst. |
| DATA C idle level | CH2 between bursts | Record level; Phase 1 read 5.11 V, against DN-02's predicted LOW. |
| MUTE polarity | CH7 in A/B/C | Record levels and observed relation to operation. Phase 1 read 0 V idle / 3.5 V enabled; DN-02 §16.4 describes active-LOW. Keep the conflict if unresolved. |

#### 4.2.3 Decode and acceptance

1. Use PulseView's SPI decoder with CH0 as CLK, CH1 as MOSI and CH2 as MISO. Set CPOL from observed CLK idle level. Try both CPHA values and both bit orders.
2. Accept the setting that yields the same frames across all three B captures. If none does, decode manually, one bit per sampling edge. Record the accepted settings or manual method, capture references and decoded frames in the TL.
3. Compare the decoded frame structure with the published protocol references, recording differences without filling unknown fields by assumption.

**Pass criteria (R-1.3):** Pre-checks recorded; A/B/C captured; every observation row filled; at least one frame decoded repeatably across all three B captures.

### 4.3 Phase 2B: Protocol Capture — With CD Changer

**Objective:** Capture bidirectional protocol traffic between the head unit and a known-working KDC-C717 CD changer connected through the breakout pass-through board (MOD-03). Observe the full initialization handshake, status polling, and changer responses.

**Entry Criteria:** Phase 2A passed. KDC-C717 changer (KEN-02) available and loaded with a known-good disc magazine. Breakout pass-through board (MOD-03) assembled, verified, and tested per TP-KRC3006-02. Logic analyzer connected per Phase 2A channel assignments.

**Reference:** Record results on Test Log Tab “Phase 2B — Changer Capture.”

#### 4.3.1 Physical Setup

1. With all power removed (both staged power adapter switches OFF), connect the breakout pass-through board (MOD-03) inline between the head unit’s 13-pin DIN port and the KDC-C717 changer cable.

2. Connect the logic analyzer probes to the breakout board’s test points using the same channel assignments as Phase 2A.

3. Load the KDC-C717 magazine with at least one known-good audio CD in slot 1. Note the total number of discs loaded and the track count of disc 1.

4. Verify all connections are secure. Confirm no signal wires are shorted to ground or power using the multimeter in continuity mode.

#### 4.3.2 Initialization Capture

1. With the source previously set to CD-CH and both staged-adapter switches OFF, start the power-on capture before applying power. Use §4.2.1 settings and the unchanged channel map (R-1.4).

2. Turn constant power ON, then ignition ON. Record the RESET pulse width and time from ignition ON to the first CLK edge in the TL power-on table; record the timing reference used. [TBD — source needed: architect method for observing ignition ON with all eight analyzer channels occupied.]

3. Select CD changer source on the head unit. Observe whether the KDC-C717 powers up, loads a disc, and begins playback.

4. Record the initialization sequence. Note:

> • The handshake sequence: which side transmits first, and how many exchanges occur before the changer reports status.

> • The timing between the head unit’s first poll and the changer’s first response.

> • Whether CH-CON (pin 4) changes state during initialization.

> • Whether CH-MUTE (pin 5) is asserted by the changer during disc loading.

5. Allow playback to stabilize for 30 seconds, then capture again to observe steady-state periodic status messages.

6. Compare the changer’s responses against the idle polls captured in Phase 2A. Identify which bytes in the response correspond to disc number, track number, and playback state.

7. During 60 s of steady playback, look for a status-frame byte that increments about once per second. Record its position and capture reference, or “none found” (R-1.4). This checks protocol time data, not the head-unit display.

8. Capture a track change and save the power-on, initialization, steady-state, time-field and track-change captures as `P2B_poweron_NNN.sr`, `P2B_init_NNN.sr`, `P2B_steady_NNN.sr`, `P2B_time_NNN.sr` and `P2B_track_NNN.sr`, with matching PNGs. Record trigger and configuration for every file (R-1.2/R-1.5).

**Pass Criteria:** Complete initialization handshake captured and decoded. Changer response message structure identified. Steady-state status message format documented. All captures saved with screenshots of key exchanges.

### 4.4 Phase 2C: CLK driver identification

**Authority:** [R-1.5, issue 2](../.agents/rulings/2026-10-16.md). **Entry:** Phase 2B passed; FIX-01 (breakout S/N 2) built and verified per DN-04 §16. Keep MOD-03 S/N 1 unmodified. Record on “Phase 2C — CLK Driver”. Phase 2C gates the HAT CLK level-shifter choice; it does not gate Phase 3.

#### 4.4.1 Fixture and Rs selection

1. With power removed, substitute FIX-01. CH0 remains on J3-11, the **changer** side of the cut. Move CH6 from RESET to CLK-H, the **head-unit** side. Other channels stay as §4.2.1. No power cycle is captured in this phase.
2. Record fixture serial, Rs value/tolerance and cable capacitances. If the DMM measures capacitance, measure DIN pin 13 ↔ pin 2 on each cable with both ends unplugged. Choose Rs ≈150 ns / the larger capacitance, rounded to 1 kΩ, 2.2 kΩ, 4.7 kΩ or 10 kΩ. If capacitances differ by more than 2×, note that changer-driven lag on the smaller side may fall below two samples.
3. Otherwise record “not measured”, start at 1 kΩ, and step through 2.2 kΩ, 4.7 kΩ and 10 kΩ as needed. Remove power before changing Rs. Never exceed 10 kΩ.
4. At every value, verify normal C717 playback and display with no error codes. If not normal, step down and record the failure. Target falling-edge lag is at least two samples (83 ns at 24 MHz), but no more than 10% of the CLK half-period measured in Phase 2A. Record that half-period and limit. If both bounds cannot be met, log an incident rather than infer direction.

#### 4.4.2 Capture and resolution

1. At 24 MHz, repeat Phase 2B's steady-state and track-change sequences through FIX-01. Save `P2C_clkdir_NNN.sr` and matching PNGs; log sample rate, trigger and configuration.
2. For each frame type, record the initiating REQ, leading side on falling edges, falling-edge lag in samples and ns, and rising-edge lead/tie. Falling edges decide: the analyzer threshold makes rising-edge lag smaller and it may appear tied (R-1.5).
3. Apply the approved resolution rules:
   - **Head-unit-driven only:** CH6 leads every falling edge by at least two samples in every frame type, and CH0 leads no rising edge. The SN74LVC8T245 arrangement stands.
   - **Bidirectional:** CH0 leads falling edges by at least two samples in some frame types. This triggers DN-01's SN74LVC1T45 fallback for CLK.
   - **Anything else:** incident, including falling-edge ties or a change of leading side within a frame.
4. Record the overall result and disposition. A two-channel oscilloscope across Rs on the same fixture may give the direction directly, if available (R-1.5); record the method used.

### 4.5 Phase 3: Command Mapping

**Objective:** Systematically map every head unit command (play, pause, next track, next disc, etc.) by pressing each button while capturing the full bidirectional protocol exchange with the KDC-C717 connected. Build a complete command reference table.

**Entry Criteria:** Phase 2B passed. Head unit and KDC-C717 are communicating and playback is functional through the breakout board.

**Reference:** Record results on Test Log Tab “Phase 3 — Command Map.”

#### 4.5.1 Systematic Button Capture

1. Ensure the KDC-C717 is in a known state: disc 1 playing, mid-track (not at the beginning or end of a disc).

2. Prepare a systematic button matrix. For each button/action on the head unit face, you will perform one capture. The buttons to test include:

> • Play / Pause

> • Next Track / Previous Track

> • Fast Forward (hold Next Track)

> • Fast Reverse (hold Previous Track)

> • Disc Up / Disc Down (or direct disc select buttons 1–6/10)

> • Repeat mode toggle

> • Random/Shuffle mode toggle

> • Any other buttons that are active in CD changer mode

3. For each button:

> • (a) Start a logic analyzer capture.

> • (b) Press the button once.

> • (c) Stop capture.

> • (d) Decode the command bytes sent by the head unit.

> • (e) Decode the response bytes sent by the changer.

> • (f) Record both the command and response hex values on the test log form.

> • (g) Save the capture file as P3_cmd\_\[name\]\_NNN.sr.

4. For commands that produce a state change (e.g., next track should cause the changer to seek and update its status), capture the full exchange including the changer’s updated status response. Note any multi-message sequences.

5. Test edge cases: press next track on the last track of a disc, previous track on track 1, disc up on the last loaded disc, and disc select for an empty slot. Record how the changer responds in each case.

#### 4.5.2 Command Map Compilation

1. Build the definitive command map table from your captures. For each command, record: the hex byte(s) sent by the head unit, the expected changer response, and any observed timing constraints.

2. Compare every byte against the Mictronics documentation. Note any commands that differ from the published protocol.

3. Identify any undocumented commands or status codes observed during testing.

**Pass Criteria:** All accessible head unit controls mapped to hex command bytes. At least play, stop, next/previous track, and disc selection confirmed. Changer responses for each command documented. Command map table complete and cross-referenced against published documentation.

## 5. Incident Reporting

When a test produces unexpected results, record a Test Incident on the “Incidents” tab of the test log workbook. Each incident should include: the phase and step where it occurred, what was expected versus what was observed, a photograph or logic analyzer screenshot if applicable, and the root cause once determined.

For an open-source project, incidents are valuable documentation. Even resolved issues should be preserved in the project repository as they help future builders troubleshoot similar problems.

Severity classification:

> • Critical: Head unit damaged, magic smoke, or safety concern. STOP all testing immediately.

> • Major: Protocol communication fails entirely; cannot proceed to next phase.

> • Minor: Specific command doesn’t work as expected, but overall protocol functions. Can proceed.

> • Observation: Behavior differs from documentation but does not affect functionality.

## 6. File Naming Convention

Use consistent naming for all captured data, photographs, and documentation throughout the project:

> • Logic analyzer captures: P\[phase\]\_\[description\]\_\[sequence\].sr (e.g., P2A_B_003.sr)

> • Screenshots/photos: P\[phase\]\_\[description\]\_\[sequence\].png

> • Test logs: TL-KRC3006-01.fods

Phase 2A uses `P2A_<config>_NNN.sr` (A/B/C); Phase 2C uses `P2C_clkdir_NNN.sr`. Every `.sr` has a matching `.png`.

Commit all artifacts to the project Git repository at the end of each test session.

## 7. Safety Precautions

> • Always verify polarity before applying power to the head unit.

> • Keep the bench PSU current limit at 2 A (raise to 3 A only if needed for startup, then reduce).

> • Remove bench power before connecting or reconfiguring analyzer probes or audio cables; verify B.U. is de-energized at the PSU/DIN connection, never at J3. Follow the blocked J3-3 and J3-1-only ground rules in §4.2.1 (R-2; DN-04 §7).

> • If any component becomes hot to the touch or produces smoke or unusual odor, immediately disconnect power and investigate before proceeding.

> • When eventually installing in a vehicle, disconnect the vehicle battery negative terminal before working on any wiring.

> • Lead-free solder is recommended. Work in a ventilated area when soldering.
