# Decisions

These are the decisions that shape how agents work on this project. The owner decides and the architect records. IDs are permanent.

| ID | Decision | Status | Outcome, or the architect's recommendation |
|---|---|---|---|
| D-1 | How to correct a published record | **Decided 2026-10-17** | Never touch the original. Publish a supplement, `{record}-S1.pdf` (e.g. `TL-KRC3006-01-P1-20260419-S1.pdf`), with the errata, the missing dispositions and the incidents, dated and initialed. List it under the original in both records tables. |
| D-2 | Revision and status scheme | **Decided 2026-10-17** | The initial release is revision "-". Later releases take letters A B C D E F G H J K L M N P R S T U V W X Y Z (I, O and Q are skipped), then AA, AB, AC … in the same pattern. Status is Draft, Released or Superseded. TP execution progress stays in the `docs/README.md` phase table. Every document gets a standard header block and a revision-history table. |
| D-3 | Authorship | **Decided 2026-10-17** | Every document and revision records who drafted it and who approved it, each with a date. Drafters are named by model, e.g. "Drafted: Claude Opus 5.5 2026-10-17", "Drafted: Codex GPT-6 Astra 2026-10-17". Approval is always "Approved: A. Kreager <date>". Log cells use the initials "AK". |
| D-4 | Lineage notes for legacy IDs | **Decided 2026-10-17** | Add a one-line "Supersedes:" entry to the headers of DN-01, DN-02, DN-03 and TP/TL-01. |
| D-5 | Where agent documents live | **Decided 2026-10-15** | In this repository: `AGENTS.md` at the root and the `.agents/` workspace. The copy of the document-control handoff in the owner's claude.ai Project is retired. |
| D-6 | Agent write access | **Decided 2026-10-17** | Branches and pull requests only. The owner reviews and merges every PR on github.com. [rules/git-workflow.md](rules/git-workflow.md) applies. |
| D-7 | `TL-KRC3006-02-01-20260401.odt` in `docs/records/` | **Decided 2026-10-17** | The PDF export already exists. Document control deletes the `.odt` in a PR (DC-12). Git history keeps the original. |
| D-8 | `assets/changer_pins.png`, a crop of the factory pin table | **Decided 2026-10-17** | Replace it with original work: a graphic of the 13-pin mini DIN port with a leader from each pin to its number and factory name (e.g. "3 B.U.", "11 DATA H"), plus a Markdown table with columns Pin, Name, Description. Assigned to a design agent, which needs a handoff first (AGENTS.md). Then remove the crop (DC-19). |
| D-9 | Test plan format | **Decided 2026-10-15** | Convert all three test plans to Markdown now (document control CP-1, skill [odt-to-markdown](skills/odt-to-markdown/SKILL.md)). Technical revisions follow as diffs. Test logs stay spreadsheets; their format is D-10. |
| D-10 | Test log format | **Decided 2026-10-15** | Flat ODF: `.fods` for the spreadsheet logs and `.fodt` for TL-02. Git stores and diffs these as text. Review changes as cell diffs ([rules/git-workflow.md](rules/git-workflow.md)), because LibreOffice renumbers styles on every save. Existing logs convert at their next change (backlog DC-20). |
| D-11 | When a live test log is committed | **Decided 2026-10-15** (the owner merged TL-01's live log) | Commit the `.fods` log when each phase completes, in the same pull request as that phase's PDF record. With cell diffs, each commit shows exactly what the phase added. This matches `docs/README.md`: the working log stays live and builds up results phase by phase. Previously the owner held a log back until all of its phases were done. |
| D-12 | Pi ↔ ATtiny UART baud rate | **Decided 2026-10-15** | Don't specify a baud rate until the hardware is tested. Documents say "set during hardware testing" instead of giving a number. The rate gets chosen and recorded during TP-KRC3006-03. |
| D-13 | Removing the GPS-tagged photos from git history | **Decided 2026-10-17** | Rewrite history with `git filter-repo`, stripping every image blob that carries GPS data, and force-push once. This is a one-time owner-run exception to "never force-push `main`". Everyone re-clones afterwards. |
