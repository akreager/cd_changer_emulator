## R-1 · DC-04 / DC-09 — Make TP-01 Rev C executable before Phase 2A

### R-1.1 Inline capture arrangement (applies to every phase)

**Signal chain:** KRC-3006 → 13-pin cable → MOD-03 S/N 1, J1 (head-unit side) → MOD-03 J2 (changer side) → KDC-C717 cable → KDC-C717. Audio is jumpered J4 ↔ J5 with a 3.5 mm TRS cable.

**Logic analyzer on J3.** The J3 pinout is from the breakout README and TL-KRC3006-02 step 3.2.

| LA channel | J3 pin | Signal (factory name) |
|---|---|---|
| CH0 | 11 | /CLK (pin 13) |
| CH1 | 10 | DATA H (pin 11) |
| CH2 | 9 | DATA C (pin 10) |
| CH3 | 6 | /REQ H (pin 1) |
| CH4 | 7 | /REQ C (pin 9) |
| CH5 | 2 | ON (pin 4) |
| CH6 | 4 | RESET (pin 7) |
| CH7 | 8 | MUTE (pin 5) |
| GND | 1 | GND (pin 2) |

- MUTE moves onto the spare CH7. Rev B left it uncaptured, but its polarity is open (R-1.4).
- **Never connect anything to J3-3 (B.U., up to ~14.4 V).** Use only J3-1 for ground; leave J3-5 (D. GND) empty. See R-2.
- Put a 1 kΩ series resistor in every signal lead (R-2).
- Before connecting, confirm that the analyzer's maximum input voltage covers the 5.15 V measured on CLK in Phase 1. `[TBD — source needed: SparkFun TOL-18627 input voltage rating]`

### R-1.2 Capture settings

The bit clock hasn't been measured; 125 kHz is an assumption.

- The first capture of each session runs at 24 MHz, the analyzer's maximum, to establish bit timing. Later captures may drop to at least 16× the measured bit rate.
- Capture length is at least 10 s. Start the capture *before* the power or source change you're studying, so the transition is inside the capture.
- Record the sample rate, the trigger and the configuration (R-1.3 letter) for every file in the Capture File Log.

### R-1.3 Phase 2A redefined

**New title:** "Phase 2A: Idle capture, changer connected, no magazine". It replaces the head-unit-only procedure. The head unit won't select CD-CH without a changer present (owner observation, to be recorded under DC-02), so the old 2A can't run as written.

**Pre-capture checks (new §4.2.0).** These carry over DN-02 §8 items 1–3.

- **Unpowered, measured at J3:** resistance to GND on pins 11 (DATA H) and 13 (CLK). DN-02 Rev C predicts ~100 kΩ (R145/R146). Record the actual value with the changer cable unplugged.
- **Powered:** pin 3 (B.U.) voltage with the source on tuner and with it on CD-CH. Expect it to stay constant. Measure at the PSU side or the DIN shell, never at J3.

**Capture sequence**, with the magazine removed so the C717 shows E-01:

| Config | Start state | Action during capture |
|---|---|---|
| A | Both staged-adapter switches off; capture started | Constant power on, then ignition on. Leave the source on tuner for 10 s. |
| B | Powered, source on tuner; capture started | Select CD-CH. Hold 15 s. |
| C | Powered, source on CD-CH; capture started | Switch the source back to tuner. Hold 5 s. |

Repeat B three times for consistency, as Rev B already required. File names: `P2A_A_001.sr`, `P2A_B_001.sr`…`003`, `P2A_C_001.sr`.

**Observations that resolve the open questions.** Each is a new TL field (R-1.6).

| Question (technical baseline, Open) | Observation | Resolution rule |
|---|---|---|
| ON (pin 4) polarity | CH5 level in A, B and C, plus a DMM reading of pin 4 with the source on tuner and on CD-CH | ON is **active-HIGH at the connector** if CH5 is HIGH only while CD-CH is selected, and bus traffic only starts after it rises, in every capture. Any other pattern is an incident. The CX85 manual's "active-LOW" may describe the changer's input after inversion (DN-02 §16.1). Record that as a note; it doesn't override the measurement. |
| CLK idle level | CH0 level between bursts, in B | Record HIGH or LOW. Phase 1's 5.15 V DC reading predicts HIGH. |
| Bit clock rate | Period of CH0 within a burst (PulseView measurement) | Record the mean and the range over 10 bursts. |
| Frame structure | CH0 edges per burst, and the order and polarity of /REQ H and /REQ C around each burst | Record which REQ line asserts first, its active level, and the bits per burst. |
| DATA C idle level | CH2 between bursts | Record it. Phase 1 read 5.11 V, against DN-02's predicted LOW. |
| MUTE polarity | CH7 level in A, B and C | Record it. Phase 1 read 0 V at idle and 3.5 V "logic high enable", while DN-02 §16.4 calls MUTE active-LOW and changer-driven. That's a new open item. |

**Decode.** Use PulseView's SPI decoder:

- Set CPOL from the observed CLK idle level.
- Try both CPHA values and both bit orders.
- Accept the setting that gives the same frames across all three B captures. If none does, decode manually, one bit per sampling edge.
- Record the accepted settings in the TL.

**Pass criteria:**
- The pre-checks are recorded.
- A, B and C are captured.
- Every row of the observation table is filled in.
- At least one frame is decoded, repeatably across the three B captures.

### R-1.5 New Phase 2C: CLK driver identification (Owner decision: build the fixture)

**Why a fixture is needed.** A logic analyzer on the connector node can't tell which side drives CLK, because both ends see the same voltage. DN-02 §16.2 asks for the driver without a method. A series resistor between the two halves of the line separates them in time: the driving side's edge crosses the threshold first, and the far side lags by about Rs·C·ln 2.

**Fixture FIX-01.** Assemble breakout S/N 2, and stop before the TP-02 pass-through checks for CLK.
- Cut the CLK trace between the J3 tap and J2, and fit Rs across the cut. Confirm the trace route in KiCad before cutting.
- Add a probe wire on the J2 side of the cut.
- Every other signal stays straight through.
- Verify it per TP-02, with CLK as a documented exception.
- MOD-03 S/N 1 stays unmodified as the reference fixture.

**Probes:** CH0 on the head-unit side (J3-11), and a spare channel on the changer side of Rs.

**Choosing Rs:**
- Start at 4.7 kΩ. With ~50 pF at the far node that's about 160 ns of lag, roughly 4 samples at 24 MHz. The real capacitance is unknown, so the measurement calibrates itself.
- If the lag is under 2 samples, use 10 kΩ. Don't go higher. With the head unit's 100 kΩ pull-down on CLK (R146), a changer-driven HIGH at the head-unit side would still be about 4.4 V.
- **Precondition at either value:** the C717 still plays with no error codes and a normal display. If it doesn't, drop Rs and record that.

**Procedure:**
- Capture Phase 2B's steady-state and track-change sequences through FIX-01 at 24 MHz.
- For each frame type, record:
  - the leading side
  - the lag, in samples and in ns
  - whether /REQ H or /REQ C started the transfer

**Resolution rule:**
- **Head-unit-driven only:** the head-unit side leads by at least 2 samples on every edge in every frame type. The SN74LVC8T245 arrangement stands.
- **Bidirectional:** the leading side changes with the frame type. That triggers the SN74LVC1T45 fallback for CLK (DN-01).
- **Anything else:** an incident.

**Ordering:**
- Entry: Phase 2B passed, and FIX-01 built and verified.
- 2C doesn't gate Phase 3. It gates the HAT's CLK level-shifter choice.
- If an oscilloscope is available, a two-channel scope across Rs on the same fixture gives the same answer directly.

## R-2 · DC-07 — Breakout protection under the corrected impedances

**Finding.** DN-04 §7 and §9 justify having no series resistors on J3 by "100K+ on CLK, DATA H and REQ H". On the corrected values (DN-02 Rev C §12), the worst cases are:

| Fault at J3 | Line | Series resistance limiting it | Fault current |
|---|---|---|---|
| A HIGH line shorted to GND | REQ H, DATA H (driven by the head unit) | 100 Ω (R144, R143) | ≈ 50 mA |
| A HIGH line shorted to GND | Lines the changer drives | 100 Ω in the CX85 (R9–R16); the C717 isn't analyzed | ≈ 50 mA |
| B.U. (~14.4 V) shorted to a signal | REQ H, DATA H into the head unit; any line into the changer | 100 Ω | ≈ 90 mA into the IC's clamp diodes |
| B.U. shorted to ON | ON | 4.7 kΩ (R142) | ≈ 2 mA |

The impedance doesn't protect anything. The procedure is the only protection. On J3, B.U. (pin 3) sits between ON (pin 2) and RESET (pin 4), and D. GND (pin 5) sits next to /REQ H (pin 6).

**Ruling.** The board is acceptable as built, with three added precautions. **Owner decision:** accepting the residual risk.

1. **Keep the power-down rule** (DN-04 §7). It's the primary protection, unchanged.
2. **Block J3-3.** Fit a cut-off pin capped with heat-shrink, or a single blank plug, so nothing can be inserted there. Measure B.U. with the DMM at the PSU or the DIN shell, never at J3.
3. **Ground only at J3-1,** and leave J3-5 empty. That removes the GND-next-to-/REQ H bridge.
4. **Fit 1 kΩ in series in every analyzer signal lead.** It limits current if a lead's far end touches B.U. or ground. It costs about 10 ns of RC with ~10 pF of analyzer input, which is negligible. It doesn't protect against a direct bridge between two J3 sockets; precautions 2 and 3 cover that.

**DN-04 Rev D text** (document control applies it):
- §5 per-pin resistances: rewrite from DN-02 Rev C §3.1/§12, giving the CX85 changer-side values as R10, R13 and R16 at 100 Ω.
- §7: replace the impedance sentence with "Source impedance doesn't limit fault current: 100 Ω on REQ H and DATA H, and 100 Ω on the CX85's side of every line. Protection is procedural." Add precautions 2–4 to the procedure table.
- §9 "No series resistors on J3": keep the decision. Replace the rationale with this ruling's, and record the owner's risk acceptance with its date.

## R-3 · DC-24 — ATtiny supply voltage and direct drive (DN-02 §3.1, §5.2, §7.7, §16.6)

**Finding.** DN-02 recommends things the later DN-01 decisions superseded:
- §5.2 and §7.7 recommend running the ATtiny1616 at 5 V, with a voltage divider on its UART TX to the Pi.
- §3.1 ("Implication for emulator") says the ATtiny's own GPIO drives the bus directly.
- §16.6 assumes "5V for Pi/ATtiny, separate 3.3V LDO for DAC".

The settled design is different (DN-01; technical baseline):
- The ATtiny runs at 3.3 V.
- The bus is driven through two SN74LVC8T245, whose B side is on 5 V.
- The UART to the Pi is direct at 3.3 V, with no divider.

**Ruling.** DN-02's *head-unit facts* stand: the µ-COM runs at 5.0–5.1 V, and the bus is 5 V logic. Those facts are why the level shifters exist. Its *emulator recommendations* in these four places are historical. Don't rewrite them; mark them.

- **§5.2 and §7.7:** add "Superseded by DN-01: the ATtiny1616 runs at 3.3 V and drives the bus through SN74LVC8T245 level shifters (B side 5 V), and the UART to the Pi is direct at 3.3 V. The 3.3 V-HIGH-through-2.2 kΩ concern doesn't arise, because the bus side is driven at 5 V." Strike the divider recommendation.
- **§3.1 "Implication for emulator":** add "The emulator drives the bus through the level shifters, not ATtiny GPIO (DN-01)." The edge-rate conclusion still holds.
- **§16.6:** keep the CX85 rail observation as context. Replace the "two-rail approach" sentence with "The HAT's supply rails are DN-01's decision; the power section isn't drawn yet (technical baseline)." Keep the LC-filter suggestion as an open recommendation for DN-01's power design.

This is a **P** change: it applies decisions already settled in DN-01. Add a Rev D history row to DN-02.

## R-5 · DC-23 — Elapsed-time display versus protocol time data

**Evidence.** The KRC-3006 instruction manual (project file `KRC3006 OM.PDF`):
- In "Clock display" (p. 2 of the scan), button ③ toggles CD changer mode between *Track No. ↔ Clock*.
- In "CD auto changer mode" (p. 15), every illustrated display shows only the track number (T-01) and the disc number.

No mode shows elapsed time. That supports DN-05 §2.2. Whether the protocol *carries* time data is unknown, and R-1.4's time-field check answers it.

**Ruling.** Display criteria test what the manual says the unit can show. Time data in the protocol is tested by capture, never by looking at the display.

## R-6 · DC-21 — How the UART baud rate gets selected (D-12)

**Review of TP-03 §4.3.2.** The plan picks "9600 (sufficient bandwidth…; reliable at 3.3 V with long breadboard wires)".

- **Bandwidth isn't the constraint.** At ~1 message/s of ~25 bytes (`STATE:PLAY:D:TT:MM:SS\n`), every candidate rate has far more capacity than needed.
- **Wire length isn't a real constraint either,** at ≤115.2 kbit/s (8.7 µs per bit) with push-pull drivers.
- **What actually decides reliability:**
  - the frame-timing error between the ATtiny's internal oscillator and the Pi's UART, across the vehicle's temperature range `[TBD — source needed: ATtiny1616 oscillator accuracy from its datasheet]`
  - command latency: the time from a head-unit button press to the Pi acting
  - a parse/checksum error rate measured on real hardware

**Ruling.** Replace the baud sentence in §4.3.2 with: "Baud rate: not specified (D-12). Select it in §4.3.2a."

**New TP-03 §4.3.2a "UART rate selection"** goes before step 3.

1. Candidate rates are 9600, 38400 and 115200.
2. For each rate, on the actual wiring:
   - **Bit-time error:** have the ATtiny transmit `0x55` continuously. On the logic analyzer that's a square wave at baud/2. Measure its frequency and compute the error in %.
   - **Soak:** exchange 10,000 STATE/command message pairs. Count framing errors and parse errors.
   - **Latency:** measure from a head-unit button press (the /REQ H edge on the bus) to the Pi's playback reaction (command logged), over 20 presses. Record the maximum.
   - If you can, repeat the bit-time error measurement cold (< 10 °C) and warm (> 40 °C).
3. **Selection:** the lowest rate with zero errors in the soak, bit-time error under a margin the architect sets once measured, and maximum latency under a limit the owner sets. Record the choice and its rationale in TL-03, then update DN-01 and DN-05 (DC-21).

**TL-03 change.** In "Phase 3 — Integration", add a "UART Rate Selection" table with columns Rate, Bit-time error (%), Temp (°C), Messages, Framing errors, Parse errors, Max latency (ms), P/F, Notes, and a "Selected rate / rationale" row.

Recommendation: the line protocol should carry a checksum, so that "parse errors" can be measured. That's a design decision for DN-01; until then, count malformed lines.
